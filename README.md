## 1. 项目概览

LexiNote 做的事只有一件：**让同一份法律英语课件，在课堂投屏、课后精读、学期末复盘这三个场景里都是同一份可交互的文档。**

法律英语的难点不在生词量，而在三件事：**术语在该语境里到底指什么**、**这句话的译文是谁给的、可不可信**、**上次读到哪里、哪个词标过**。因此项目把三条约束做成了系统能力，而不是写进宣传语：

| 约束 | 工程实现 |
| :--- | :--- |
| **可对照** | 术语是编辑器里的独立节点（`legal-term`），点开即取 `vocabulary_entries` 的注音与释义；「对照译文」按句哈希查预置句库，命中给译文，未命中如实标注 |
| **可溯源** | 每条生词带来源类型（课件 / 笔记 / 讨论 / 手动）、来源文档与原文语境；学情里的每个数字都能点回到具体的人与文档 |
| **可离线** | `node:sqlite` 单文件数据库，无外部服务、无第三方统计、无字体 CDN；`npm install` 后即可跑，不需要原生编译 |

### 1.1 一句话边界

| 项 | 结论 |
| :--- | :--- |
| 输入 | 教师创建的课件与笔记（Tiptap JSON）、学生标注、讨论帖与回复、生词 |
| 输出 | 可交互阅读页、整屏演示、生词本（xlsx / docx / 打印 PDF）、课程学情 |
| 形态 | 桌面浏览器为主（1440 宽；侧栏 + 正文 + 目录三栏）；演示态按投影设计 |
| 部署 | 单机单进程，一个 Node 进程 + 一个 SQLite 文件；无 Redis、无对象存储 |
| 不做什么 | 不做机器翻译、不做自动答题与代写、不接教务系统、不做跨校多租户 |

### 1.2 技术面貌

`Next.js 14 App Router` · `Tiptap 2` · `node:sqlite` · `jose` · `zod` · `exceljs / docx` · 25 个页面 · 37 个接口 · 22 张表 · 约 1.4 万行 TypeScript

## 2. 核心链路

```text
教师建课 → 建班（生成 6 位班级码）→ 创建课件 → 编辑（术语 / 要点 / 图片 / 流程图）→ 发布
                                                                              │
学生注册（学号即账号）── 凭班级码或邀请链接入班 ── 自动选修该班课程 ──────────┘
                                                                              │
                                                                              ▼
                        阅读工作台（三态：阅读 / 编辑 / 演示）
                          ├─ 点术语 → 释义卡 → 加入生词本（带来源与语境）
                          ├─ 选句子 → 对照译文 → 命中给译文，未命中标注
                          ├─ 选中文字 → 悬浮工具条（B / I / H1–H3 / 列表 / 引文 / 要点 / 标为术语）
                          └─ 演示 → 整屏一屏一段，滚轮一格翻一屏
                                                                              │
                                     ┌────────────────────────────────────────┤
                                     ▼                                        ▼
                          讨论区（提问 / 作业 / 批注 / 评分 / 参考答案）   生词本（自定义 + 内置术语表）
                                     │                                        │
                                     └──────────────► 学情（选课数 / 课件数 / 译文命中率 / 未掌握词 / 术语热度）
```

关键点在两处：

- **术语不是高亮文本，是节点**。删除、复制、跨文档粘贴都保留 `entryId`，所以释义永远能回到词库里的那一条，不会退化成一段加粗的字。
- **演示不按标题切页**。页面里放一份同宽同字号的离屏副本，量出每个顶级块的真实高度再装箱，因此每屏互不重叠，滚轮拨一格正好一屏。

## 3. 设计底线

| # | 底线 | 落实方式 |
| :---: | :--- | :--- |
| 1 | **释义不编造** | 释义只取自 `vocabulary_entries`（内置词库或用户自建）；词条不存在就不显示释义，不让模型现编 |
| 2 | **译文不机翻** | `translation/match` 按句哈希查预置句库；未命中原样标注，界面写明「未命中」 |
| 3 | **数据不出机器** | 单文件 SQLite；无第三方统计、广告、字体 CDN、外部 API 调用 |
| 4 | **口令不落明文** | `scrypt` 加盐散列（`scrypt$salt$hash`），比对用 `timingSafeEqual` |
| 5 | **会话可收回** | httpOnly Cookie + JWT；不勾「记住」是浏览器会话 Cookie，勾了 30 天 |
| 6 | **班级即权限** | 课程挂班后禁止直接选修（403）；成员移除、班级码重置校验教师身份 |
| 7 | **演示一屏一段** | 按真实版面高度切屏；标题不落页尾、大标题下至少跟一段正文；单块超屏按比例缩小，不出内部滚动条 |
| 8 | **校本信息不入库** | `data/` 整目录被 `.gitignore` 排除：数据库、本校课程安排、术语表导出 |
| 9 | **失败要显式** | 保存失败、译文未命中、词库缺失都写清楚；词库缺失时整套内置词库跳过，不假装有内容 |
| 10 | **角色不越权** | 侧栏按角色裁剪（学生只有学习与帮助）；`/admin` 与学情仅 TEACHER / ADMIN 可见 |

## 4. 功能矩阵

| 能力 | 说明 |
| :--- | :--- |
| **课程与班级** | 教师建课、建班；建课时「授课班级」既可从已有班级里挑，也可直接填班名当场建班（服务端发 6 位码，同名班级自动复用，不重复建）。班级码字符集去掉 `0/O/1/I`，可重置、可关闭自助加入；支持邀请链接（可设次数与有效期）；学生入班自动选修该班课程，幂等。班级可由建班教师**解散**：课程解绑保留、学生选课与笔记不动，只清掉成员关系与邀请 |
| **教材库** | 课程所用教材按讲次导入，`/textbooks` 书架 → 单本目录 → 章节阅读三跳。章节是 `documents` 里的 `TEXTBOOK` 类型，正文只读，直接复用阅读工作台的术语、译文、生词与演示；读书目元信息存在独立的 `textbooks` 表 |
| **英文法律专题** | 中国现行法律的英文官方译本按部门法分 7 类归档，`/readings` 下方专题入口 → `/readings/laws` 目录 → 单篇阅读。篇目是 `documents` 里的 `LAW` 类型（154 篇、约 71 万词），同样只读并复用阅读工作台；目录页可按法名检索、按类收起，分类内按官网发布日排序 |
| **阅读工作台** | 阅读 / 编辑 / 演示三态。术语点开有注音与释义，可一键收进生词本；「对照译文」按句匹配；右侧目录吸顶 66px 并独立滚动，滚正文时不被顶栏遮住 |
| **悬浮工具条** | 有选区时贴选区上方（贴顶落下方），无选区停在视口底部，可折成右下角 `Aa` 圆钮；按钮 `mousedown` 拦截，点按钮不丢选区 |
| **整屏演示** | 纸面铺满视口，字号随投影视口缩放；浮层 2.6 秒无操作淡出；`F` 进浏览器全屏、`Esc` 先退全屏再退演示；`?p=3` 从第 N 屏进入 |
| **生词本** | 每人两个默认词表：**自定义单词本**（空）+ **法律英语单词本**（内置 2,208 条）；四档掌握度；服务端分页 40 条/页、搜索、A–Z 字母索引；导出 xlsx / docx / 打印 PDF |
| **全站检索** | 页面底部常驻一条搜索栏（按 `/` 聚焦），任何页面都能直接查全部文档正文（课件、教材、英文法律、笔记）。FTS5 `trigram` 索引，中英文子串都匹配：`consid` 能命中 consideration，`合同法` 能命中正文与术语释义。术语节点的**中文释义也进索引**，所以搜「对价」能找到只标注了 consideration（对价）的段落。不足 3 字符的短词自动走 LIKE 后备（trigram 的硬限制）。结果一律按可见范围过滤，别人的未发布课件不会出现在结果里 |
| **AI 辅助（可选）** | 三类按需能力：句级译文草稿、术语语境释义、学情诊断摘要。**不填 `AI_API_KEY` 即完全关闭**，界面不出现任何 AI 入口，行为与接入前一致。所有生成内容标注「AI 草稿」，须教师审校才转正式（`/admin/translations`），驳回的句子不再重复生成 |
| **讨论与批注** | 提问与作业分开建帖；教师可在回复上写批注、打分、标记参考答案；回复计入学习记录与学情活跃度 |
| **学情** | 选课人数、课件数、译文命中率、未掌握词数、术语热度；逐人明细并进「教学班 · 成员名单」同一张表（学号 / 姓名 / 笔记 / 术语 / 收录词 / 回复 / 译文 / 加入方式），一页只有一份学生清单。未掌握词只统计自建词表，不被内置词库稀释 |
| **课程安排** | 本学期八个专题与配套案例（含案号出处）、上课周次、课程代码；每个专题下的「课件」直接跳到这一讲的正文，案例有电子稿时同样可点。右侧推荐阅读栏收录 10 种教材，可按书名 / 作者 / 出版社 / **ISBN（可省连字符）** 检索。同一页下半部分是**英文法律专题**的 7 类入口，点进去按目录读全文 |
| **隐私政策与使用条款** | `/privacy` 与 `/terms` 为公开路由（不登录可读），正文按「汉字序号 + 1.1 式条款」分条撰写，左侧点状目录随滚动高亮、右下角回到顶部；登录页页面底栏与每页右下角均有入口。登录后 `/help` 是完整操作手册，三份文档共用一条吸顶侧边目录，章节随滚动高亮 |
| **导出** | 同一份 `WordbookExportDTO` 喂三个渲染器：exceljs（xlsx）、docx（Word）、打印样式（PDF） |

## 5. 快速开始

```bash
# 需要 Node >= 22.5（依赖内置 node:sqlite，无需原生编译）
npm install
npm run db:seed     # 重建 SQLite 并灌入演示数据（会清空旧库）
npm run dev         # http://127.0.0.1:3100
```

> **为什么是 `127.0.0.1` 而不是 `localhost`**：本机若开着系统代理（Windows「设置 → 网络和 Internet → 代理」）
> 且未配置例外地址，浏览器会把 `localhost:3100` 也交给代理转发，代理不认识这个本地主机名，直接返回 **502**，
> 表现就是「页面打不开」。`127.0.0.1` 是明确的本地 IP，代理客户端按本地地址放行，同一服务用 IP 能开。
> 所以文档、入口页、启动脚本一律写 `127.0.0.1`。

Windows 上也可以双击 **`打开平台.cmd`**：先探测 3100 端口，没服务才拉起 dev，然后直接打开登录页（`http://127.0.0.1:3100/login`）。

### 5.2 接入 AI 辅助（可选）

**不配置即关闭。** 要开启，把 `.env.example` 复制为 `.env.local`，填入三项即可：

```bash
AI_BASE_URL=https://api.deepseek.com/v1   # 任何 OpenAI 兼容接口
AI_API_KEY=sk-...                          # 留空则整块功能关闭
AI_MODEL=deepseek-chat
```

| 变量 | 默认 | 说明 |
| :--- | :--- | :--- |
| `AI_ENABLED` | 视 key 而定 | 填了 key 即启用；设 `0` 可强制关闭而不必删 key |
| `AI_TIMEOUT_MS` | `15000` | 单次调用超时。单进程架构下这个值直接决定最坏响应时间 |
| `AI_MAX_CONCURRENCY` | `2` | 同时进行的模型请求上限；超出排队 8 秒，仍排不上就直接降级 |

已验证的兼容供应商：DeepSeek、通义千问（`dashscope.aliyuncs.com/compatible-mode/v1`）、
智谱 GLM（`open.bigmodel.cn/api/paas/v4`）、本地 Ollama（`127.0.0.1:11434/v1`）。
换供应商只改 `AI_BASE_URL` 与 `AI_MODEL`，代码不动。

**数据边界**：只发送用户选中的课文句子或词语及其所在句，不发送姓名、学号、班级、
笔记正文与讨论内容；调用日志只记字符数、耗时与成败。详见隐私政策第 4.4 条。
若所在机构禁止将教学材料发往外部服务，改用本地 Ollama 即可，其余不用改。

模型不可用时，所有 AI 入口自动隐藏或降级为原有文案（「暂无预置译文」），
**不会把错误抛到界面上**。

## 6. 账号班级与权限

**账号即学号。** 注册时输入学号与姓名，登录用学号，不设用户名。

### 6.1 口令策略（注册时校验）

- 至少 8 位；不得等于学号或姓名；
- 至少含两类字符（大写 / 小写 / 数字 / 符号）；
- 拒绝弱口令表、连续串（`123456`、`abcdef`）、单字符重复（`aaaaaaaa`）；
- 界面提示：**不要使用与学校系统相同的口令**——本平台与学校统一身份认证没有打通，重复使用会放大泄露面。

### 6.2 入班三种路径

| 路径 | 说明 |
| :--- | :--- |
| 注册时填班级码 | 注册成功即入班并自动选修该班课程；班级码错误只返回 `joinWarning`，**不废掉注册** |
| 登录后按码加入 | 班级页输入 6 位码，或点邀请链接 `/join/<token>` 落地 |
| 被邀请 | 教师生成邀请链接，可设最大使用次数与有效期；`used_count` 满或过期即失效 |

### 6.3 角色可见范围

| 角色 | 可见 | 不可见 |
| :--- | :--- | :--- |
| STUDENT | 课程、课程安排、班级、文档、生词本、讨论、使用说明 | 学情、维护者说明 |
| TEACHER | 以上全部 + 学情 + 维护者说明 | — |
| ADMIN | 同教师 | — |

| `data/lexinote.db`（含 `-wal` / `-shm`）| 账号、姓名、学号、笔记、生词、讨论、学习记录 |
| `data/course-plan.local.json` | 本校课程安排：任课教师、教室、周次、课程代码、专题与案例 |
| `data/glossary.zhang-falian.json` | 由自备电子版生成的法律英语术语表（版权原因不入库） |

- **课程安排**：照 `data/course-plan.local.json` 的字段结构填写即可；文件缺失时页面退回仓库自带的示例安排，不会报错。
- **术语表**：`node tooling/scripts/extract-glossary.mjs <你的 xlsx 路径>` 生成；文件缺失时内置词库整套跳过，生词本只剩「自定义单词本」，其余功能不受影响。
- **教材正文**：`npm run textbook:import` 把分讲 Markdown 转成 Tiptap 写进 `data/lexinote.db`，**不进仓库**（版权原因）。`data/` 与教材 Markdown 源目录都在版本控制之外，换部署机需要重跑一次导入。书目元信息写在 `tooling/scripts/import-textbook.mts` 的 `BOOKS` 里，可复现。
- **英文法律正文**：`npm run laws:import` 读本机归档目录 `npc-laws-en/`（154 份 Markdown，按 `01`–`07` 分部门法），剔除官网页面残留的 `Contents` 目录块后写入 `documents`（`kind = 'LAW'`）。分类骨架（名称、顺序、说明）在 `apps/web/src/server/content/legal-library.ts`，不建表。源目录同样在版本控制之外；换机器需先自备归档或改脚本里的默认路径。
- **隐私政策**：`/privacy` 按本项目的实际实现撰写（scrypt 加盐散列、httpOnly 会话 Cookie、数据只落本机、无第三方统计与广告）。部署到自己的环境前，请核对「谁在处理你的数据」「联系」两节是否与事实一致。
- **备份**：`.db` 与 `-wal` / `-shm` 必须一起复制；只拷主库会丢掉最近的写入。
- **提交前自查**：`git grep 教师姓名\|教室\|课程代码` 应为 0 命中。

```bash
NODE_OPTIONS= npm run build                        # 生产构建（含类型与路由表生成）

```

| 保障项 | 机制 |
| :--- | :--- |
| 类型 | `tsc --noEmit` 全仓 strict，含 `packages/*`；`next build` 会再过一遍 |
| 规范 | `npm run lint` 扫描 `apps/web/src` 下 154 个 ts/tsx，0 错误 0 警告。规则取 `next/core-web-vitals` 默认强度，只把 `react-hooks/exhaustive-deps` 降为 warn、关掉 `@next/next/no-img-element`；故意不开 `no-console`——服务端降级路径（检索索引失败、AI 调用失败）需要留日志 |
| 单元测试 | `npm test` 用 Node 内置 `node:test`（零框架依赖）跑 40 条，覆盖三处「错了不报错、只是慢慢失真」的纯函数：SM-2 排期（首次 1 天 / 第二次 6 天 / 上限 180 / ease 下限 1.3 / 不改入参）、口令规则与散列（长度、弱口令、连续字符、中文放行、往返校验）、句子归一化与哈希（空白、弯引号、破折号、省略号，同句不同排版必须同哈希） |

## 10. 已知限制

| 范畴 | 限制 |
| :--- | :--- |
| **测试** | 单元测试只覆盖三个纯函数（SM-2 / 口令 / 归一化）与检索、接口两套脚本；页面与数据权限仍靠人工巡检与截图，改动越大越容易漏。接口与检索脚本依赖本地内容导入，未进 CI |
| **账号** | 没有自助改密与找回；忘记口令只能由维护者后台重置。演示账号口令统一，**不可用于真实部署** |
| **译文** | 按句子哈希匹配预置句库，覆盖不到的内容如实标注；不做机器翻译，也不做译文的行内编辑 |
| **版本** | 快照与 `diff` 接口已具备（`/api/documents/[id]/snapshots`、`/diff`），**尚无对比界面** |
| **学情** | 有班级汇总与逐人行为，学生端也能看到自己的阅读记录；但**只记「打开过哪份课件」，不记停留时长、滚动深度与读完比例**——这些需要前端埋点与时长聚合，当前没有 |
| **内置词库** | 从自备 xlsx 抽取，清洗时丢弃了纯序号行与 OCR 残行；仍可能残留个别错拼，遇到请以教材为准 |
| **教材术语标注** | 导入时按内置词库自动标注，规则是「多词术语全收 + 单词术语要求唯一释义、长度≥5、非常用词」，约每 100 词 6 处。词库本身含 will（遗嘱/助动词）、but（but-for test 截断条目）、There（释义与词形不符）这类同形或残缺条目，全量标注会造成明显误导，因此宁可少标。个别多义泛词（information / question / interest）仍可能标在非法律语境上 |
| **教材覆盖** | 首批只导入何家弘《法律英语》第四版 25 篇；张法连上下册的 Markdown 已整理但尚未入库，在 `BOOKS` 里补一条并重跑导入即可 |
| **英文法律译本** | 正文取自全国人大官网英文版，官网标为 Translation for Reference Only：**译本供参考，不具法律效力**，引用条文以中文正式文本为准。归档时间为 2026-11-02，此后新修法需重跑 `laws:import` |
| **法律篇目结构** | 154 篇里有 65 篇是「决定 / 办法」这类无章节的短文本，右侧目录为空属正常；另有少数长篇的官网译本本身缺少 `Chapter` 标记（如刑法分则部分章节），目录项会少于条文实际分章 |
| **并发** | 单机单进程设计，`node:sqlite` 无连接池；多实例部署前需换数据库与锁方案 |
| **移动端** | 只保证可读；演示态按桌面投屏（16:9）设计，手机竖屏不适合投屏分屏 |
| **学术边界** | 只做阅读辅助与讨论，不提供代写、自动答题或成绩判定 |
